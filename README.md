# Greater Victoria open map (demo)

A small web map of Greater Victoria, built by Claude, an AI model, for Darren Zal. It is a demo of an open, self-hostable alternative to embedding Google Maps for local groups in Greater Victoria. It shows watersheds, creeks (with animated flow direction), parks, ecosystem zones, terrain shading and a 3D terrain view (both on when the page opens) from open data, plus an optional layer for events and places. Optional layers add seafloor depth, ecoregions, industry and waste sites, marine life and protection (protected marine areas, killer whale critical habitat, a whale and porpoise density model and coastal habitat from an old survey), and live data from outside services (precipitation radar, sea currents, wind, sea temperature, sea saltiness, tides and tidal currents, weather alerts, air quality, current conditions, river gauges, earthquakes and life observations). It is a demo. It is not an official map of any group.

Status: published at https://darrenzal.github.io/greater-victoria-map/ (code in https://github.com/DarrenZal/greater-victoria-map). Built on 2026-10-21. Data retrieved 2026-10-21, except the marine life and protection files (2026-10-22).

Repository name `greater-victoria-map`. The code is under the MIT licence, see [LICENSE](LICENSE) (Darren Zal, 2026). The MIT licence covers the code only. Each data layer keeps its own licence, recorded per layer in [data/SOURCES.md](data/SOURCES.md), and the MIT licence does not relicense any of it. The vendored MapLibre library keeps its own BSD-3-Clause licence in [vendor/MAPLIBRE-LICENSE.txt](vendor/MAPLIBRE-LICENSE.txt), which must stay with it.

## Run it locally

It is plain static files with no build step. From this folder:

```sh
python3 -m http.server 8000
```

Then open http://localhost:8000/. Opening `index.html` straight from disk will not work, because browsers block module scripts and data requests on `file://` pages.

The page needs internet for the street basemap (tiles.openfreemap.org), for the elevation tiles (s3.amazonaws.com) behind Terrain shading and 3D terrain, which are on by default, and for each live layer (api.weather.gc.ca, geo.weather.gc.ca, earthquake.usgs.gov, api.gbif.org, api.tidesandcurrents.noaa.gov, and api-iwls.dfo-mpo.gc.ca for the Victoria Harbour gauge) once its box is ticked or its station is clicked. Seafloor depth draws its ETOPO1 colours from the same elevation tiles and, while its box is ticked, also asks nonna-geoserver.data.chs-shc.ca (the Canadian Hydrographic Service) for tiles. The seven Marine life and protection boxes make no request to any outside host either: each loads one file of this site when it is first ticked. If the basemap cannot be reached, the page shows the data layers on a plain background and adds a sentence to the banner. If a live service cannot be reached, its layer shows a plain failure line.

## What is on the map

Default on: the example place, creeks, lakes and wetlands (with Flow, below), parks and green spaces, terrain shading, 3D terrain, municipal boundaries. Default off: watersheds, ecosystem zones, seafloor depth, ecoregions, industry and waste sites, the seven marine life and protection layers, and the twelve live layers. Clicking a feature opens a popup with its name, type and source. Popups are built from plain text only, and only https links are clickable.

**Flow.** A sub-toggle under "Creeks, lakes and wetlands", on by default. Pale dashes march downstream along the creek lines from zoom 9 up, so a visitor can see which way Bowker Creek, the Colquitz River or Craigflower Creek drain. It shows drainage direction from provincial lines, not discharge or current. Reaches the Province maps as main flow in a natural channel, and reaches it maps as canals, get dashes. Pipes (subsurface flow) and connection lines do not, and the panel and credits say so. Canals were added on 2026-10-21: Bowker Creek now shows about 1,420 m of its roughly 2,110 m mapped length (about 480 m of natural channel and 940 m of canal), where it showed about 480 m before, and the other 680 m, mapped as subsurface flow, stays undashed. Under a system setting of reduced motion the layer is hidden altogether, the box is off and disabled, and the page follows the setting if it changes. The animation loop runs only while the dashes can be seen: the Flow and creeks boxes are on, this tab is in front and the map is zoomed to 9 or more. How the direction was found and checked is in [data/SOURCES.md](data/SOURCES.md).

**Terrain shading.** A hillshade drawn in the browser from AWS Terrain Tiles. On by default (since 2026-10-21, at Darren's request). Credits and the on-map attribution name the sources while it is on. With both terrain boxes unticked, no elevation tile is requested.

**3D terrain.** On by default (since 2026-10-21, at Darren's request): the map opens flat and tilts into relief once it has loaded, with no animation when the device asks for reduced motion. The box lifts the map into relief with MapLibre's terrain support, from the same AWS Terrain Tiles (a second source on the same tile address, because MapLibre warns that one source shared with the hillshade lowers the quality of both). The exaggeration is 2 (`TERRAIN_EXAGGERATION` in [js/app.js](js/app.js), 1 is true height). The map tilts to 60 degrees (`TERRAIN_PITCH`), drag-rotate, two-finger tilt and the compass are switched on, and a sky and fog are added. Unticking it removes the terrain and puts the pitch and bearing back to 0. While it is off, the map is flat and north-up and rotation is locked. The Terrain shading box stays independent of it. The relief has no lighting of its own, so the note under the box says Terrain shading gives the hills their light and shade. The parks, creeks, watersheds and the other flat layers are draped over the relief by MapLibre, and the check queries them with 3D on. The Flow dashes step at half the rate while 3D terrain is on, because each step redraws the draped creeks. Performance was not measured on a phone, see "Not tested yet" below.

**Ecoregions.** Off by default. The RESOLVE Ecoregions 2017 polygon for the area, loaded from this site on the first tick. The whole demo box falls in one ecoregion, Puget lowland forests, and the shape is a coarse copy, so the layer is a label for the region more than a map. See [data/SOURCES.md](data/SOURCES.md).

**Industry and waste sites.** Off by default. Eighteen sites in the box: 11 landfills and waste sites, 6 wastewater plants and pump stations and one power plant. Only records from sources whose licences were read as open are used. A dot with no figures is a location, not an empty site, and every figure says whether it was reported, is a capacity or is modelled.

**Live data.** Twelve layers, grouped under "Live data" in the panel, off by default. Nothing is requested from an outside service until its box is ticked, and the panel says so. The tide and current stations are the one exception to "on tick": ticking Tides and tidal currents shows the stations from a list in the page, and NOAA, or the Canadian Hydrographic Service for the Victoria Harbour gauge, is asked only when a station is clicked. Each shows a plain status line, and a plain failure line if its request fails (the alerts line also says that the map is then not showing whether any alert is in effect). Each is loaded straight from the visitor's browser, so there is no key and no server of ours in between.

**Sea currents.** Off by default, in the Live data group. Ticking it asks the GeoMet service which hours the model offers, then for the two velocity components (east and north, in metres per second) of the latest hour not after now. The box asked for is west -124.5, south 47.8, east -122.6, north 49.2 (everywhere the map can go, with a margin), asked with `scalefactor=0.5`, so the service sends every second cell of its 500 m grid as two GeoTIFF images of 117 x 155 cells (73,018 bytes each, 146 KB an hour, against 235 x 311 cells and 586 KB without it; measured 2026-10-22: 7,495 of the 18,135 cells are sea, and every cell of the half-size grid equals a cell of the full one, so it is subsampled, not averaged). [js/overlays-data.js](js/overlays-data.js) reads them with a small GeoTIFF reader (one band of 32-bit floats, not compressed, little- or big-endian) and refuses anything else, and treats NaN, a value above 100 m/s and exactly zero in both components as no data (that is how the model marks land). [js/flow.js](js/flow.js), the particle engine shared with Wind, turns the grid into a velocity field in screen pixels on a grid of points every 7 px. It asks the map which place lies under a lattice of points every 28 px (`map.unproject`, so pitch, rotation and 3D terrain are followed) and turns the slope of longitude and latitude over the screen into the direction the water goes on the screen. Rows above the horizon of a steeply tilted view are left out, because `map.unproject` answers there with places behind the camera. About 4,000 particles (1,500 where the window is narrower than 700 px, fewer where less sea is in view) are dropped on sea points, carried along the field and drawn as short segments that fade into trails: darker, thicker and longer for faster water. The trails are blue, from a mid blue for slow water to deep navy above 0.8 m/s, because the basemap's sea is pale grey (#c2c8ca): the contrast of each band against it is 3.7 to 9.4 to 1, where the white and pale cyan used first had 1.2 to 1.9 to 1. A particle that reaches land, the edge of the model or the end of its life (1.5 to 3.5 s) starts again on the sea. The canvas is drawn over the map and under the popups and the panel, and lets every touch through. While the map moves the picture is cleared and the loop paused, and it starts again when the map stops. The loop also stops when the tab is hidden or the box is unticked, which removes the canvas. The pace on the screen is the same at every zoom: the velocity field is scaled by the typical pixels per metre of the view (`fieldScale` in [js/overlays-data.js](js/overlays-data.js), the middle value over the field), so 0.5 m/s moves about 30 px a second (`pxPerMs` 60, `FLOW_PROFILES` in [js/flow.js](js/flow.js)) whether the view is the whole strait or a bay, measured in the browser check as 58.8 to 60.0 px a second for each m/s at zoom 8.6, 10.4 and 12.5. Tilt is kept, so far water still moves less on the screen than near water, and a particle never moves more than 10 px in a frame. The note under the box gives that pace and no single speed-up factor, because a factor would be false at other zooms (the picture is about 2,700 times faster than the real water at the opening zoom of 10.2, and about 400 times faster at zoom 13). The status line names the model hour in Pacific time ("Modelled surface currents for Oct 21, 10 p.m. PDT, Environment Canada’s CIOPS Salish Sea model (experimental, not for navigation)."). Play steps one hour every 1.5 s through the 13 hours from now (one tide cycle is a little over 12). It fetches each hour when it is wanted and the next one ahead, keeps up to 14 hours in memory so a second loop makes no requests, and stops when Pause is pressed. It does not start by itself. Under reduced motion nothing moves: each particle is drawn once as a short streak that fades in toward the way the water goes, longer for faster water, and Play is disabled with the reason given. The credit on the map is the Environment and Climate Change Canada Data Server End-use Licence statement, the same as the other Environment Canada layers, and the credits panel, the status line and the note call the model experimental and not for navigation. The picture is a drawing of a model, not a measurement. Clicking the sea while the layer is on opens a popup with the modelled current at that point for the hour shown: the speed in knots and metres per second, the compass point the water flows toward ("flowing toward the north-east", from eight points), the hour, and "Model estimate, not for navigation". It reads the grid already loaded, makes no request, and says "Almost still" with no direction below 0.03 m/s. Every other popup is unchanged: a click on a pin, park, creek or other feature opens that popup alone, and on water inside a municipal, ecosystem-zone or ecoregion area the current comes first and the area's own popup follows it. With the layer off, or with Wind on, a click on the sea shows no current.

**Wind.** Off by default, in the Live data group, next to Sea currents. It is the other half of what [earth.nullschool.net](https://earth.nullschool.net) shows, drawn with the same engine, over land and sea, in purple (deep plum above 9 m/s) so it is not mixed up with the blue currents. Ticking it asks the GeoMet service which hours the HRDPS layer `HRDPS.CONTINENTAL_WSPD` offers (2026-10-22: `2026-10-22T06:00:00Z/2026-10-24T06:00:00Z/PT1H`, 49 hours), then for the wind speed (`HRDPS.CONTINENTAL_WSPD`, metres per second, 10 m above the surface) and the wind direction (`HRDPS.CONTINENTAL_WD`, degrees) of the latest hour not after now, over the same box as the currents, asked as `scalesize=x(57),y(62)`: 57 x 62 cells of about 2.5 km, the model's own spacing, 14,562 bytes each, 29 KB an hour (measured). The service has no east and north wind layer for WCS (`HRDPS.CONTINENTAL_UU` answers "WCS request not enabled"), so [js/overlays-data.js](js/overlays-data.js) makes the east and north components from the two (`windGrid`) before anything is interpolated, because directions cannot be averaged. The direction is the one the wind blows from, clockwise from north, checked on 2026-10-22 against 25 station reports across Canada with a speed of 15 km/h or more: the model direction was within a median of 9.6 degrees of the station when read as "from" and 170.4 degrees when read as "to" (see [data/SOURCES.md](data/SOURCES.md)), so a wind from the west (270) blows east and the particles move that way, which the static self-test checks for all four compass directions and north-east. The speed is in metres per second, not knots or km/h (the layer title says so, a feature query gave 3.35 m/s for the class "5 - 10 kts", and the stations' km/h over the model's m/s came out at about 4.5, not 1.9). Every cell with a number is data, and exactly calm is data too, because wind blows over land. The particles move at 12 px a second for each m/s (5 m/s is about 60 px a second) at every zoom. There are about 4,000 on a wide screen and 1,500 on a narrow one. Sea currents and Wind cannot both be on: ticking one unticks the other, because there is one canvas and one engine, and the one that goes off drops its hours from memory. The status line names the hour and the model ("Modelled wind for Oct 22, 4 a.m. PDT, Environment Canada’s HRDPS model (forecast, not for navigation)."). Play, Pause, the hours kept, reduced motion (still streaks, Play disabled) and the credit work as for Sea currents. Wind has no click readout.

**Sea temperature and Sea saltiness.** Off by default, in the Live data group, next to Wind. They are two more fields of the model behind Sea currents (CIOPS-SalishSea, 500 m, hourly, a 48-hour forecast), asked for as pictures from the GeoMet WMS and drawn like the radar, as one image laid over the map area ([js/overlays.js](js/overlays.js), `scalar`). Ticking one asks the layer's own description (17 to 18 KB, 48 hours on 2026-10-22: `2026-10-22T07:00:00Z/2026-10-24T06:00:00Z/PT1H`), then one `GetMap` for the hour shown, in web Mercator at 720 x 767 pixels over the same area as the radar (32,311 bytes for the temperature and 43,612 for the saltiness in the last run on 2026-10-22, measured, and 32,580 and 43,688 an hour earlier). The hour shown is the one of Sea currents while that layer is on, and it steps with that layer's Play (the next hour is fetched ahead while it plays, no more). With Sea currents off it is the latest hour not after now, and it goes back to that when the currents are switched off. The pictures kept are the small PNG replies (14 hours at most), so a second loop of Play makes no request, and unticking lets them go. The model marks land as no data, so the picture covers only sea (about 46% of the image is model sea). The picture sits above the basemap's sea and the sea masks of the ecosystem zones and ecoregions, and under the creeks, parks, boundaries and labels, at 0.6 opacity. Measured in the browser check with the picture and the basemap's water at the same places, under 10% of the picture lies over basemap land (3 to 5% in the views tried, because the model's cells are 500 m) and nearly all the water in view is covered. The particles of Sea currents are drawn on a canvas over the map, so they stay above the picture. The colours are the service's own and the style was chosen by trying every style the layer offers (see [data/SOURCES.md](data/SOURCES.md)): the temperature uses `SEA_TEMPSURF-DEFAULT`, which keeps one colour scale all year, and the saltiness uses `SEA_SALT-COASTAL`, which spends its colours between 20 and 32 psu. The service's own colour keys are not used: the temperature key is in kelvin and its bar does not line up with the colours the picture uses (measured). The key under each box is made by hand from colours measured in the picture (`SCALES` in [js/overlays-data.js](js/overlays-data.js), 6 to 18 degrees Celsius and 20 to 32 psu) and is checked against the service in the browser check: at 8 places across the sea, the colour in the picture is within 25 of 255 in each channel of the key's colour for the value the service reports there (the largest difference measured on 2026-10-22 was 2 for the temperature and 9 for the saltiness in the last run, and 1 and 6 in an earlier one). Clicking the sea while one is on adds a line to the popup, "Surface sea temperature: 11.5 °C (for Oct 22, 5 a.m. PDT)." or the saltiness in psu, from one small `GetFeatureInfo` request for that place and the hour shown (`info_format=application/json`, a 3 x 3 pixel request around the point, the value in kelvin turned into degrees Celsius). With Sea currents on, it comes under the current in the same popup. With only a temperature or saltiness picture on, a click on the basemap's water opens its own popup. Land, an hour out of range and a failed request each give a plain line and no number. The status line, the credits and the readout say experimental, model estimate and not for navigation. The credit on the map is the Environment and Climate Change Canada statement, as for the other layers from that service.

**Tides and tidal currents.** Off by default, in the Live data group. Ticking it shows eight dots from a list in [js/overlays-data.js](js/overlays-data.js) (`TIDE_STATIONS`): three water level stations (Port Angeles 9444090 and Friday Harbor 9449880 from NOAA and Victoria Harbour 07120 from the Canadian Hydrographic Service, in teal) and five tidal current stations (Race Rocks PUG1640, Discovery Island PUG1636, Haro Strait PUG1718, Trial Island PCT1391 and Cattle Point PCT1416, in violet), each with its service's own name. All eight returned data on 2026-10-22 and none was dropped. Ticking asks NOAA and CHS nothing. A click on a NOAA dot asks the NOAA CO-OPS data API for that station: the highs and lows (water level) or the slacks and maximums (currents), from 8 hours before now to 30 hours after, and, for the five stations that give one, a series every 30 minutes for the curve. That is 2 requests of about 1 to 9 KB each for five stations and 1 for the two (Trial Island and Cattle Point) that give only slack and maximum times at every interval. The requests name the application (`application=greater-victoria-map`, as NOAA asks of its callers), ask for UTC and are made once for each station while the box stays ticked: the same station opened again makes no request (unless it was last asked for more than six hours ago, so that the next event stays ahead of now), and an unticked and ticked box starts fresh. Nothing polls NOAA. The popup lists the next events soonest first with times in Pacific time (heights in metres above chart datum MLLW, speeds in knots, flood above zero and ebb below it), says which way flood and ebb flow and, for a current station, how far below the surface the prediction is for (60 ft at Race Rocks, 28 ft at Discovery Island, 66 ft at Haro Strait, 15 ft at Trial Island, none given at Cattle Point), and draws a small SVG of the 24 hours from three hours before now, with a red marker for now. The curve is NOAA's own series. For Trial Island and Cattle Point it is drawn between the events by an easing from each to the next, and the popup says so. It never presents the result as NOAA's: "Drawn here from NOAA's numbers. Not official NOAA material." and "Predictions, not for navigation." are in every popup, and the credit on the map is "NOAA/NOS/CO-OPS" with a link to its disclaimer, and, for Victoria Harbour, "the Canadian Hydrographic Service" with a link to its licence agreement. NOAA says its information is in the public domain and asks for attribution, and its disclaimer says that information shall not be modified in content and then presented as official government material (read 2026-10-22, quoted in [data/SOURCES.md](data/SOURCES.md)). The popup shows a plain line if NOAA cannot be reached.

**Victoria Harbour tide gauge.** Part of Tides and tidal currents, from the Canadian Hydrographic Service (CHS), Integrated Water Level System (IWLS), station 07120 (id `5cebf1df3d0f4a073c4bbd1e`). It is the only CHS station used. A click on its dot asks `https://api-iwls.dfo-mpo.gc.ca/api/v1/stations/<id>/data` three times, 0.4 seconds apart because the service allows 3 requests a second and 30 a minute for each client: `wlp-hilo` (the highs and lows for the next 30 hours, about 0.6 KB), `wlo` (the observed water level of the last 3 hours, every 5 minutes, about 4.6 KB) and `wlp` (the predicted level from 3 hours before to 21 hours after, every 15 minutes, about 12 KB), about 17 KB in all, in UTC. The same station opened again within 15 minutes makes no request, an unticked and ticked box starts fresh, and nothing polls the service. The popup gives the next high and low tide soonest first, the level the gauge last measured with its time ("Observed 11:50 a.m. 2.41 m", in Pacific time, metres above chart datum) and the same 24 hour curve as the NOAA stations with the observed levels drawn over the predicted ones up to now in a darker line, and a key. The high and low events come with no type, so the page tells a high from a low by the neighbours. A reading the service flags as questionable is dropped, so the level shown is never one. The observed levels are real-time readings that the service had not reviewed on 2026-10-22, and the popup says so. Only the highs and lows are needed: without the other two requests the curve is drawn between the highs and lows and the popup says so, or says the observed levels could not be loaded. The popup carries the licence's required notice word for word, a plain line if the service cannot be reached, and a link to the station page (https://tides.gc.ca/en/stations/07120). The IWLS licence (https://tides.gc.ca/en/licence-agreement, dated 2023-08-14, read 2026-10-22, recorded in [data/SOURCES.md](data/SOURCES.md)) bars derivative products made for commercial purposes, for sale or profit. This is a non-commercial demo. It asks for the notice "in a prominent location" on a derivative product, so the notice is in the popup, in the panel under Tides and tidal currents while the box is ticked, in the credits and here. With "Darren Zal" in the place the licence leaves for the user's name, it reads: This product is not to be used for navigation. The incorporation of the Data in this product does not constitute an endorsement or an approval of this product by the Canadian Hydrographic Service, the Department of Fisheries and Oceans or His Majesty the King in Right of Canada. A real browser does not say it.

**Seafloor depth.** Off by default, in the Water group. The sea coloured by depth in metres, with one key, from two sources. In Canadian waters it is the Canadian Hydrographic Service's NONNA bathymetry (100 m cells, and 10 m cells from map zoom 11), asked for live from CHS by the visitor's browser while the box is ticked. Everywhere else, and under the CHS colours, it is NOAA's ETOPO1 grid, drawn in the browser with MapLibre's `color-relief` layer over a copy of the elevation source with its own limit (`seafloor`, tile zoom 8 at most) on the same tile address as Terrain shading and 3D terrain. The key runs from 0 to 300 m in the same blues for both, with ticks at 10, 50, 100, 200 and 300 m.

*ETOPO1.* The colours run from a pale blue at 25 m to a dark blue at 300 m, fade in from 10 m and are transparent from there up to the waterline and above, which leaves land alone. The grid is 1 arc-minute (about 1.2 by 1.85 km here) in the tiles, so it shows broad shapes only: no small channels, reefs or shore depths, and none for the inner waters, and nothing shallower than 10 m is coloured where it is the only source (the U.S. side). The tile limit of 8 was chosen by measuring (2026-10-22, see [data/SOURCES.md](data/SOURCES.md)): from tile zoom 9 the land data masks the sea near the coast to 0 m, which left a hole in the colours round Victoria's waters at 9 and 10, and from zoom 11 the sea is flat 0 m everywhere. From the zoom 8 tile the colours stay smooth at every zoom.

*CHS NONNA.* The CHS server draws depth in its own fixed colours (red shallow, then yellow, green, blue and navy) and has no other style, so the colours cannot be asked for in this map's blues. Each tile is fetched by the page's own `nonna` address (`addProtocol` in [js/app.js](js/app.js), `loadNonnaTile` in [js/overlays.js](js/overlays.js)), handed to a worker ([js/seafloor-worker.js](js/seafloor-worker.js)) that reads every pixel's colour back to a depth and paints it again in the key's colour, and given to MapLibre as a raster tile. The ramp was fitted on 424,060 places where the service's own depth grid (WCS) and its picture were compared (a straight line in colour between six points, root mean square error 0.5 to 1.2 of 255), and the read-back is good to about 0.1 to 0.25 m down to 30 m, about 2 m to 100 m and 8 to 20 m beyond, where one step of colour is 16 to 21 m (the deep end is in bands). Land and heights above chart datum (the service's brown) and anything shallower than 1 m are left uncoloured. The tile already carries the layer's 0.75 opacity, mixed with the basemap's sea colour, and is opaque where it has depths, so the coarser ETOPO1 colours under it do not show through. Where the service has no data (the U.S. side, land) the tile is clear and the ETOPO1 colours show. The service's own pictures have a hairline with no data where two of its 0.1 degree sheets meet, so a run of one or two pixels with no data between pixels that have it, and a one or two line gap along the edge of a tile, is filled in the worker (`nonnaFill`), and wider gaps are left. A tile of 256 by 256 pixels is a few hundred distinct colours. The 100 m layer is used below map zoom 11 and the 10 m layer from there, to tile zoom 14, because at zoom 11.6 the 10 m tiles show channels and banks where the 100 m cells are squares. Tiles measured on 2026-10-22, each view in a fresh browser: in a 1280 by 800 window 24 tiles (379 KB) at the opening zoom of 10.2, 40 (413 KB) at 9.6, 48 (2.07 MB, about 43 KB each, the 10 m layer) at 11.6 and 12 (286 KB) at 13.6, and at 390 px wide 8 (373 KB) at its opening zoom of 9.4, 15 (254 KB) at 9.6, 18 (763 KB) at 11.6 and 6 (122 KB) at 13.6. The 10 m tiles are about three times the size of the 100 m ones, and the browser keeps each tile for a day (the server's `cache-control`). If that is too much for a phone, the 10 m layer can start at a higher zoom (`NONNA_CLOSE_ZOOM` in [js/overlays-data.js](js/overlays-data.js)). Nothing is stored here: the worker works on one tile at a time and the page keeps only the answer for each colour it has met. Where a worker, `OffscreenCanvas` or the service is not available the tiles fail, the status line says that the Canadian Hydrographic Service's depths could not be loaded and that the coarser ETOPO1 depths from NOAA are shown, and they are. The failure line shows only while no tile has arrived, and goes when one does. The notice the NONNA licence requires "in a prominent location" is in the panel under the box while it is on, in the credits and here. With "Darren Zal" as the user, it reads: This product was made by Darren Zal and contains intellectual property of the Canadian Hydrographic Service (CHS) of the Department of Fisheries and Oceans. ## Left out on purpose

None of these is in the demo, and none is linked.

- **Native Land territories, languages and treaties.** Its Data Sovereignty Treaty (https://api-docs.native-land.ca/data-sovereignty-treaty) lists "Store or distribute API data without explicit permission from Native Land Digital." as prohibited, so a copy of the polygons in this repository is out. Every API request needs a key tied to one person's agreement, and a static page cannot keep a key secret. Native Land Digital's own pages disagree (one says the data can be treated as CC0, the Treaty and FAQ say otherwise), so the stricter text governs. It needs Native Land Digital's written permission first. See open item A2.
- **RUSH rain garden map data and any link to RUSH.** Excluded until RUSH agrees.
- **HydroSHEDS HydroBASINS and HydroRIVERS.** The rights review is not recorded as cleared. The rivers file is 73 MB and 500 m resolution. The Freshwater Atlas replaces both.
- **Records, graph and people from the [Salish Sea Atlas](https://salishsee.life) project, and Indigenous place names.** Publishing Indigenous place names needs the Nations' permission, which has not been sought. The Atlas's industry and waste snapshot, ecoregion tiles and its live-layer endpoints were used as sources of data and methods, not its code.
- **Industry and waste sites from sources with unclear or share-alike licences.** The Atlas snapshot has 995 sites in the Salish Sea. Of the 29 in the demo box, 18 are shown. Dropped: 10 modelled river-plastic outfalls (points with no name, from a model, not sites), one wastewater plant named for a First Nation (this demo shows no First Nations content and no Nation has been asked, so the name is left out until someone decides), and every record from Climate TRACE (its terms list external datasets with other terms), IMF PortWatch (IMF terms) and Maus et al. mining footprints (CC BY-SA). Where a site has an open record and a Climate TRACE record, only the open record is used.
- **A Natural Resources Canada earthquake feed.** Looked for on 2026-10-21 and not found in a form a browser can read: the Earthquakes Canada site answered HTML with no Access-Control-Allow-Origin header, and no JSON or GeoJSON address was found. The U.S. Geological Survey catalogue is the only earthquake source.
- **Canadian Hydrographic Service data beyond two uses.** The owner accepted the CHS licences on 2026-10-22 for the NONNA seafloor tiles and the Victoria Harbour tide gauge (IWLS) only, both asked for live from the visitor's browser and never stored (see Seafloor depth and Tides and tidal currents). Every other IWLS station (the current stations Race Passage, Juan de Fuca East, Active Pass, Tillicum Bridge and Johnson Street Bridge, and the predictions-only stations such as Sooke and Clover Point) and every other CHS product is not used, and no CHS file is in this repository.
- **DFO Rockfish Conservation Areas and shellfish closures, seal haulouts.** No licence was found for the first two, and haulout positions are sensitive.
- **Whale sightings, whale-watch boats and ship tracking.** No live or recent sighting position and no AIS vessel position is shown anywhere: that would send boats to whales. Only modelled density and the critical habitat boundary are shown, with the vessel distance rules (Transport Canada Ship Safety Bulletin 08/2026: at least 1,000 m from Southern Resident killer whales from 2026-06-01 to 2027-05-31, 200 m from other killer whales, 100 m from other whales, dolphins and porpoises, from the Marine Mammal Regulations). The Life observations layer drops every whale, dolphin and porpoise record.
- **The vessel restricted zones and speed restricted zones of the Transport Canada bulletin** (Pender Island, Saturna Island and Swiftsure Bank). No machine-readable file of them was found, and they are not digitised by hand, so they are not drawn. The bulletin's own maps are "for visual representation only and must not be used for navigation or enforcement".
- **Parts of the CRIMS and PRISMM data that cannot be read safely.** The seabird colonies' nesting counts (their species codes have no dictionary, so no species is named), the kelp biomass (its unit is not given), the herring spawn index and egg fields (zero in these records) and the fin whale (its cells are not in the Salish Sea grid).
- **Indian Reserves, Sensitive Ecosystems Inventory, Water Licensing Watersheds.** Held for a later decision. Water Licensing Watersheds is "Access Only", not open data.

## Adding pins

Edit [data/pins.geojson](data/pins.geojson) on GitHub or in a pull request. A pin appears only if `status` is `approved`. No invented events: a pin is added only once its organiser has confirmed it. Every property is plain text.

| Property | Meaning |
|---|---|
| `id` | short unique name |
| `kind` | `happening`, `learning-journey`, `partner-event` or `example-place` |
| `title` | shown in the popup and as the map label |
| `summary` | plain text, 300 characters or fewer |
| `date` | text, optional |
| `place_name` | text, optional |
| `url`, `url_label` | an https link and its text (the organiser's own page for partner events) |
| `source_url` | an https link to the source of the facts |
| `status` | `draft` or `approved` |

The geometry is a `Point` with `[longitude, latitude]`. For events at private homes use a public place or round to about 100 m. Do not add private addresses or named private individuals without their consent. The popup tag and the empty-state text follow `kind`, so adding a real event needs no code change. The Layers panel label still reads "Example place" and counts every pin, so rename it when real events go in. While no real pins exist, the Layers panel says "No events listed yet."

If pins later come from a Google Sheet, publish only a separate tab that holds approved rows. "Publish to the web" exposes every row of the published tab, so a status column alone does not keep drafts private. CORS on a published sheet has not been tested.

## Checks

```sh
node scripts/check-demo.mjs            # static checks, plain Node, no dependencies
node scripts/check-demo.mjs --browser  # also runs the headless browser checks
```

[scripts/check-demo.mjs](scripts/check-demo.mjs) first proves each "must not contain" rule can fire, by running it on seeded bad input, then checks this folder: no held-layer file names (native-land, rush, hydro, person), no email addresses, phone numbers, tokens or private path markers in the page, data, README and fetch script (not in LICENSE, the other scripts or the git history), every URL on an allowed host, no root-relative paths, pin rules (status, kind, https links), a size limit of 10 MB, every layer file present with valid GeoJSON inside the demo box, the licence statement, banner and credits present, and the vendored MapLibre files matching their pinned checksums. ## Refreshing the data

[scripts/fetch-layers.sh](scripts/fetch-layers.sh) downloads the layers from the BC Data Catalogue WFS and rebuilds `data/*.geojson` with mapshaper 0.7.93 and, for the flow lines, [scripts/make-flow.mjs](scripts/make-flow.mjs) (plain Node). Its last section rebuilds the seven marine files from the CPCAD, Fisheries and Oceans Canada and CRIMS services (and [scripts/make-density.mjs](scripts/make-density.mjs) for the density cells), and `ONLY=marine sh scripts/fetch-layers.sh` runs just that section and leaves every other data file as it is (it was run that way on 2026-10-22, once with the downloads and again with `FETCH=0` to rebuild from them). Run it on a developer machine, never from the browser, then run the checks and commit. Set `FETCH=0` to reprocess already-downloaded files in `raw/` (which is not committed). On 2026-10-21 the whole script, download step included, was run from scratch. It reproduced seven of the committed layers byte for byte, changed `greenspaces.geojson` (Capital Regional District rows removed) and created `streams-flow.geojson`. The Islands Trust row was filtered out of the committed file for a time and put back on 2026-10-21 from the earlier local build of the file. Because the simplifier ranks vertices across the whole layer, a full run can differ from the committed `greenspaces.geojson` by a few vertices in that row and in other parks.

[scripts/make-industry.mjs](scripts/make-industry.mjs) builds `data/industry-waste.geojson` from the Salish Sea Atlas snapshot `material-sites-salish.json` (pass its path as the first argument). It keeps sites inside the box from the three open sources, drops every other source's records, the river-plastic kind and the site named for a First Nation, and keeps each figure's basis in words. `data/ecoregions.geojson` was made once, from the Atlas's `ecoregions-2017.pmtiles` (`pmtiles extract` for the box, then the z8 tile decoded to GeoJSON and clipped with mapshaper 0.7.93), and checked against the RESOLVE UTFGrid tiles at four points. The steps are in [data/SOURCES.md](data/SOURCES.md).

## Hosting

The site is served by GitHub Pages, deployed from the `main` branch, root folder, at https://darrenzal.github.io/greater-victoria-map/. It is plain static files, so there is no build step. Every path in the page is relative, so it works under the project path. `.nojekyll` stops GitHub from running Jekyll over the files.

After each deploy:

1. Run `curl -sI -H 'Accept-Encoding: gzip'` on the three `.mjs` files under `vendor/` (`maplibre-gl.mjs`, `maplibre-gl-shared.mjs`, `maplibre-gl-worker.mjs`) and expect `content-type: text/javascript` and `content-encoding: gzip`. If `.mjs` were served with the wrong type, load MapLibre from the jsDelivr copy of 6.9.0 instead.
2. Open the page on a phone and a desktop, confirm the demo banner and attribution show, and open the example popup.

The repository is public, so its history is public too. Before pushing, run both checks and scan the repository for personal paths, email addresses and tokens. Updates: edit pins in the repository, or refresh the provincial data with the fetch script.

Visitor privacy: the page uses no analytics and no cookies. Map tiles come from tiles.openfreemap.org, so that service receives visitors' tile requests. Terrain shading and 3D terrain are on by default, so elevation tiles come from s3.amazonaws.com on every visit until a visitor switches both off, and Amazon Web Services receives those requests too. The credits say so. If a visitor ticks a live layer, their browser, with its internet address, contacts the service behind it: Environment and Climate Change Canada (api.weather.gc.ca for alerts, air quality, conditions and gauges, geo.weather.gc.ca for radar, sea currents and wind), the U.S. Geological Survey (earthquake.usgs.gov), GBIF (api.gbif.org) when a station of Tides and tidal currents is clicked, the U.S. National Oceanic and Atmospheric Administration (api.tidesandcurrents.noaa.gov) or, for Victoria Harbour, the Canadian Hydrographic Service (api-iwls.dfo-mpo.gc.ca), or, while Seafloor depth is ticked, the Canadian Hydrographic Service's tile server (nonna-geoserver.data.chs-shc.ca). The privacy note in the credits names each of these hosts. All of them answer browsers directly (Access-Control-Allow-Origin: *, checked with curl and an Origin header on 2026-10-21, for NOAA and the two CHS hosts on 2026-10-22, and by the requests the browser check makes from a page on another origin), so no proxy or key is needed. The IWLS service sets a load-balancer cookie on its replies (the tile server does not). A page's fetch does not send or keep cookies for another site, so none is stored in the visitor's browser. The tile notes say the elevation bucket is meant for efficient use from EC2 and is not behind a CDN, so a busy public site should host pre-extracted tiles instead. That matters more now that terrain is on by default. A self-hosted Protomaps extract of the Greater Victoria area (about 3.6 MB at zoom 13) would remove that third-party request, but needs hosted fonts and sprites and is about a day of work.

Risks: OpenFreeMap is a single-operator service with no SLA and can change or stop without notice, the boundaries are provincial and approximate, and a public repository makes the data files and the pins history public. The live layers add more of the same: each depends on a service that can change or stop, GBIF refuses a burst of requests (the loader asks one at a time and reports a partial result), and a busy public site would send many visitors' requests straight to Environment Canada, the USGS, GBIF, NOAA and the Canadian Hydrographic Service (one picture a visitor for each hour of Sea temperature or Sea saltiness, one small request for each click on the sea while one is on, one or two for each tide station opened, three for the Victoria Harbour gauge, which the service limits to 3 a second and 30 a minute for each client, and a few dozen tiles of 16 to 43 KB each for each view of Seafloor depth, from a server whose uncached tiles can take several seconds). Environment Canada's usage policy was read on 2026-10-22 and is quoted in [data/SOURCES.md](data/SOURCES.md). The USGS and GBIF terms were not read beyond the licences quoted there, and GBIF's own terms page could not be fetched from the live site (see open item A6).

  - Native Land Digital (territories, languages, treaties, by API): written permission from Native Land Digital, via https://native-land.ca/contact. Its pages say the data is for non-commercial and educational use, with attribution and acknowledgement of Indigenous communities as stewards. Its "What We Map" page says territories will no longer be provided through the API (undated), so languages is the likelier layer.
  - First Peoples' Map of B.C. (First Peoples' Cultural Council), https://maps.fpcc.ca/page/tos: language regions, place names and band offices. The terms are copyright with no open licence and forbid copying, merging or publishing the data. An iframe embed with acknowledgement is allowed, and API use needs approval from the Council. Language regions are not territory.
  - Reserves (Aboriginal Lands of Canada Legislative Boundaries, Natural Resources Canada, https://open.canada.ca/data/en/dataset/522b07b9-78e2-4819-b736-ad9208eb1067): Open Government Licence - Canada, usable with attribution. Legal reserve parcels under Indian Act names, not traditional territory, so how they are labelled is a Nation-relations question.
  - First Nations Location (Indigenous Services Canada points, https://open.canada.ca/data/en/dataset/b6567c5c-8339-4055-99fa-63f92114d9e4): Open Government Licence - Canada. Administrative office locations, not territory.
  - Historic Treaties (Crown-Indigenous Relations, https://open.canada.ca/data/en/dataset/f281b150-0645-48e4-9c30-01f55f93f78e): Open Government Licence - Canada. One island-wide Douglas Treaties estimate for Victoria, "for informational and representational purposes only".
  - BC Data Catalogue First Nations layers (treaty areas and lands, community locations) and BC Geographical Names with the Indigenous tag: "Access Only", so written permission from the Province is needed (its Copyright Permission Request Form).
  - Nation-published material (the W̱SÁNEĆ Leadership Council's SENĆOŦEN place names map, the Songhees, Esquimalt, T'Sou-ke and Scia'new websites, the Te'mexw Treaty Association statement of intent map): no reuse terms found, so each needs the Nation's or the body's permission. The treaty-association map shows preliminary negotiation boundaries from the early 2000s.
- **A3.** RUSH. Nothing about RUSH is included unless RUSH agrees.
- **A4.** Environment and Climate Change Canada licence. The live layers use the End-use Licence read on 2026-10-21 (version 2.1.1, August 2026). The Salish Sea Atlas credits the same radar to the Open Government Licence – Canada, which the licence page does not say. The Open Government Portal record for CIOPS-SalishSea, the model behind Sea currents (https://open.canada.ca/data/en/dataset/cccb0064-5ab3-416a-a4f0-566b54f466f3, read 2026-10-22), lists the Open Government Licence – Canada, while the data server's licence page and the GeoMet service (`AccessConstraints` None, no attribution statement) point to the End-use Licence. The page credits the End-use Licence only, as for the other layers. Wind (HRDPS) is credited the same way: its model page (read 2026-10-22) points to the same End-use Licence and the same usage policy, and the Open Government Portal record of HRDPS was not read. Sea temperature and Sea saltiness, from the same CIOPS-SalishSea model through the same service, are credited the same way. Before the page goes public, decide whether to keep the statement the licence prescribes when a service names none, and re-read the licence for any change (its section 9 says the version in force when the data was accessed governs). Stations run by other bodies (NAV CANADA, PC-NRMB, and the B.C. Ministry of Environment for one gauge) are named in popups as the licence asks, and the Parks Canada code PC-NRMB is shown as published, not expanded.
- **A5.** Ecoregions and industry sites. The ecoregion polygon is a generalised copy (z8 tiles of the Atlas), not the 150 MB official shapefile, and the shape of the coast comes out coarse. Statistics Canada's Open Database of Infrastructure landing page (https://www150.statcan.gc.ca/n1/pub/34-26-0003/342600032023001-eng.htm) was unavailable on 2026-10-21 (a maintenance page), so its wording rests on the Atlas's record of 2026-09-24, and the Open Government Licence – Canada text itself was read on 2026-10-21. Ten of the eleven landfill points are unnamed "Facility mixed" locations. The wastewater site named for a First Nation is left out (see "Left out on purpose"). River-plastic outfalls could be added back as a separate, clearly modelled layer.
- **A6.** GBIF's data user agreement (https://www.gbif.org/terms/data-user) returned HTTP 403 to curl and to the browser tool on 2026-10-21 (Cloudflare), so it was read from the Internet Archive copy of 2025 (last updated 16 August 2017). It says users "must comply with the terms and conditions included in the licence selected by each Data Publisher", that "the identifier of ownership of data must be retained with every data record shared onward for reuse" and that "it is forbidden to use APIs to create denial of service". The layer keeps each record's dataset and licence, and asks for 300 records once per tick. Re-read the live page before launch.
- **A7.** NOAA CO-OPS terms. The disclaimer was read on 2026-10-22 and is quoted in [data/SOURCES.md](data/SOURCES.md): the information is in the public domain and attribution is asked for, and it "shall not be modified in content and then presented as official government material". The page draws curves from NOAA's numbers and says in every popup that they are not official, and it shows no number as NOAA's own. No rate limit or usage policy for the data API was found on its documentation page, so the page makes one or two small requests for each station opened and none otherwise. Read the API page again before launch. The three Puget Sound current stations (Race Rocks, Discovery Island, Haro Strait) are predictions from current surveys of seven weeks to four months in 2016 and 2017.
- **A8.** The colours of Sea temperature and Sea saltiness are the model service's own, so they can change with the service. The styles are named in [js/overlays-data.js](js/overlays-data.js) (`SEA_TEMPSURF-DEFAULT`, `SEA_SALT-COASTAL`) and the keys were measured on 2026-10-22. Anything outside the tested range (a temperature below 10 or above 13 degrees Celsius, a saltiness below 20 psu) was not tested against the Salish Sea itself. The browser check tests the key against the service every time it is run, so a change would show. The temperature style spreads its colours over about 30 K, so the Salish Sea's few degrees are a narrow band of turquoise to green. Another style or a picture drawn in the browser from the model's numbers would show more, and was not tried.
- **A9.** Seafloor depth. (1) Where ETOPO1 is the only source (the U.S. side, and under the Canadian Hydrographic Service tiles) it is only as good as the grid in the elevation tiles (1 arc-minute, about 1.2 by 1.85 km here, with the inner waters and anything shallower than 10 m left uncoloured), and the tile limit of 8 rests on the tiles as they were on 2026-10-22 (from zoom 9 the land data masks the sea near the coast to 0 m). If the tile service changes, measure again. (2) In Canadian waters the depths are read back from the colours the CHS server draws (see open item A11), good to a fraction of a metre in the top 30 m and to bands of 16 to 21 m below 100 m, and the shallowest metre is left uncoloured. A better source would be the service's depth grid itself (WCS), which is a float per cell and about 12 times the size of the picture for the same area (545 KB against 45 KB for a box of 333 by 301 cells), and was used only for the checks. (3) GEBCO's WMS (public domain, 15 arc-seconds) was the fallback if CHS had not been accepted and was not used.
- **A10.** Marine life and protection. (1) CPCAD is compiled by Environment and Climate Change Canada, but its record (https://open.canada.ca/data/en/dataset/6c343726-1e92-451a-876a-76e17d398a1c, modified 2026-03-25) and its service say Open Government Licence - Canada, so it is credited to that licence, while the Environment Canada weather layers are credited to the End-use Licence (A4). If the records are wrong about the licence, both change. (2) The no-take line rests on CPCAD's `NO_TAKE` field ("Marine Resource Use": All, Part, None, not reported, not applicable). No data dictionary for it was found, so All, Part and None are read as how much of the area is no-take, which gives All for the four ecological reserves and None for the Gulf Islands marine zones. Ask the CPCAD team (the record's contact) before the page is public. (3) The density cells are a model of summer 2018 surveys with a coefficient of variation of 0.3 to 1.3, so a cell is a rough guide and the page says so. Killer whales are not in the model, and the Southern Resident critical habitat is a legal boundary, not a map of where the whales are. (4) The vessel distances are quoted from the bulletin and the regulations as read on 2026-10-22 and the 1,000 m rule runs only to 2027-05-31. The Fisheries and Oceans Canada flyer was not read again. Re-read all three before launch, and if the Interim Order is renewed or changes, change `WHALE_RULES` in [js/overlays-data.js](js/overlays-data.js), the credits and the checks together (the check keeps its own copy of the sentence, so a change in only one place fails). (5) The Pender, Saturna and Swiftsure zones are not drawn (see "Left out on purpose"). Ask Fisheries and Oceans Canada or Transport Canada for a file before anyone digitises them. (6) CRIMS is old: kelp and eelgrass mapped from 1979 on (eelgrass in 1998), herring spawn recorded from 1937 to 1986, and no plans to update it. It is shown as old data and not as a current record. (7) The seabird colonies are positions of nesting areas from that survey. They are low risk to publish at this age, and the popup asks visitors to keep well back, but seabird and kelp locations are not checked against anything newer. (8) Fisheries and Oceans Canada's Rockfish Conservation Areas and shellfish closures, seal haulouts, and Canadian Hydrographic Service data stay out (see "Left out on purpose").
- **A11.** Canadian Hydrographic Service (CHS). (1) The IWLS and NONNA licences were read on 2026-10-22 and are recorded in [data/SOURCES.md](data/SOURCES.md). The owner accepted them for the two uses here. The IWLS licence bars derivative products made for commercial purposes, for sale or profit, so this stays a non-commercial demo: ask CHS (the licence page gives a contact) before the map carries a fee, sponsorship or any commercial use. Whether a public non-commercial demo is a derivative product at all is not settled by the text, and the notice is shown either way. (2) Both notices name "the User", and "Darren Zal" is filled in. If the demo is taken over by a group, change `CHS_USER` in [js/overlays-data.js](js/overlays-data.js), the credits and this README (the checks fail until every copy agrees). The IWLS notice has no full stop at its end, as in the licence. (3) Each licence ends when CHS posts a public notice on its site, and asks the user to destroy copies within 15 days. Nothing is stored, so ending the use means removing the two calls, but the licence pages and the Open Government Portal record should be watched. (4) The colours and the sheet seams are the tile server's own (its style is called `raster` and it has no other). The ramp in `NONNA_RAMP` can drift if CHS changes it, and the browser check compares the page's colours with the service's own depth grid every time it runs. (5) The tile server's uncached tiles took 0.3 to 9 seconds on 2026-10-22 and a cached one about 0.2 seconds, and no usage policy or rate limit was found for it. (6) The painting needs a module worker and `OffscreenCanvas` in the worker (Chrome, Edge, Firefox 114 or later and Safari 16.4 or later). Where one is missing the tiles fail, the plain line shows and the ETOPO1 colours remain. This was not tried in Safari or on a phone. (7) The IWLS service answers a user agent that says "HeadlessChrome" with HTTP 500 and no CORS header, so a headless check must give another user agent, as the browser check does. A real visitor is not affected.
- **Data edge.** The data layers end at the demo box, except the seven marine files, which end at the edge of the area the map reaches. On a wide screen the home view shows the western edge of the data near Sooke (about 123.75 W), where layers stop and the basemap continues. A wider box costs file size.
- **Creek length.** The Freshwater Atlas has 12 named Bowker Creek segments, about 2.1 km of a creek the 2012 Blueprint measures at 9.4 km, because piped stretches are unnamed or unmapped. The popups say so.
- **Watershed sizes.** The Province draws the Bowker Creek watershed at 1,381 ha. Other sources use other figures. The watershed popup says other groups draw watersheds differently.
- **Dependency on a newer MapLibre.** MapLibre 6.9.0 is pinned because it is the version already in use and tested in the related [Salish Sea Atlas](https://salishsee.life) project. Later releases exist, and an upgrade is a later, deliberate step. Version 6.x has no UMD file, so the page loads MapLibre as an ES module.
